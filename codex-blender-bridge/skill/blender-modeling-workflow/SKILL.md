# Blender 建模工作流

适用于当前 GUI Blender、独立后台 Blender，或两者结合。遵循 `$collaborate-with-liqinlei` 的项目、授权和交付规则；制作静帧或动画时同时遵循 `$make-3d-videos`。本技能约束的是**建模过程与验收**，不是让所有任务都使用某一种造型算法。

## 开工：先看现状与能力目录

1. 确认项目工程、参考图、用途（展示、游戏、打印、动画等）、交付格式和单位。读取适用的项目 `AGENTS.md`；已有工程先记下原文件路径、对象、集合、材质、修改器与当前选区。修改用户工程前保留可恢复版本。
2. 探测本机通道：GUI 可见时先读 `doctor` 和场景；后端可用时**先调 `plan` 的 `catalog`**，按任务展开相应 family，再调该 family 的 `*_help`。不要凭旧文档猜 op 或参数。仅插件可用时先调 `modeling_modules`、`modeling_catalog` 和模块 `help`。命令与安装位置见 [本机连接](references/local-bridge.md)。
3. 选最合适的执行方式：人在 GUI 前、需要交互选件与改一步看一步时用 GUI；批量、耗时或可重复生成的步骤用独立后台进程/worker。GUI 暂停 AI 写操作时尊重暂停；对 GUI 写入前取得后端租约或使用插件的本机命令。

## 从参考到可编辑模型

1. **冻结规格。** 明确坐标系、前向轴、实际尺寸/比例、对象清单、关键接口、材质方向和验收标准。参考图没标尺时只写相对比例；需要毫米尺寸时先做标定，并记录标定依据。
2. **按形体选能力。** 基本硬表面先查 `geo`/`shape`，规则重复用阵列，开孔用布尔且保留切割件，曲面用 `surface`/`sweep`，有机形体用 `sculpt`，多零件用 `assembly`，参考图量测用 `img`/`calib`，白模与多视图用 `blockout`。以当前 `catalog` 和 `help` 为准；没有合适 op 时才直接写 `bpy`/`bmesh`。
3. **小步建模。** 先白模和主体轮廓，读回尺寸与多视角画面；再做结构、接口、修改器、材质和细节。每个关键阶段保存工程版本，并留截图、量测或操作回执。复杂多件模型不要一次生成到底才检查。
4. **检查实际外观。** 用交付视角及必要的侧、顶视角检查比例、轮廓、厚度、接触点、穿插与遮挡；数字检查不能代替画面检查，画面也不能代替尺寸和拓扑检查。参考图比对必须同机位、同裁切、同尺度；单视图 IoU 不等于整体相似。

## 检查网格、装配和交付

- 单件：查 `audit_mesh`、必要时 `fix_*`，关注非流形边、零面积面、松散点、法线、自交、三角面量和实际尺寸。修复后重新审计。`ok=true` 只说明操作执行；结论看 `verdict/state`，`degraded` 不是通过。
- 多件：查 `asm_scan`/`audit_*` 的接口、浮空、干涉和隐藏交叠；设计允许的交叠要在规格中声明。只对有依据的缺陷修复，修后从另一视角或另一检查路径复核。
- 交付：先保存可编辑 `.blend`，再按用途导出 GLB/FBX/OBJ 等；读回导出文件或用独立 Blender 进程重新导入，核对对象数、尺寸、材质/贴图、法线和动画（若有）。需要项目级门时跑 `gate_*` / `deliver_*`；门未通过时不要写成“验收通过”。交付说明标出实际完成、未验证项和源文件位置。
- 小改动可只重查受影响对象与最终视角；新模型、拓扑变更、装配或正式交付应走完整检查链。

## 能力边界

本机接入的是 Blender 插件、建模 Python 模块和独立 Node 后端；`blender-modeling-workflow` Skill 自身不运行模型，也不自动给 Blender 面板加按钮。第三方素材和 3D 生成服务要用各自账号，未配置或未实际调用时不可声称生成成功。目录能列出操作不等于每个操作都在当前 Blender 版本通过；出现错误先按回执诊断，必要时退回 `bpy` 或后台 Blender 的可复现脚本，并保留同等验收。
